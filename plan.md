# System status, progression and army upgrade plan

## Product and implementation approach

Extend the existing vanilla-JS, mobile-first PWA in place. Do not introduce a framework, external service, database, paid API, billing, or new Firebase rule. Preserve the existing `sys90` local-first state, Google-authenticated Firestore document and sync flow. Store all additions under `S.system`; continue storing Website records under `S.websites`. Existing activity, XP, level, streak, log and Website fields remain in place. Initialize rank once from the current saved XP if `S.system` is absent; afterwards rank advances only by the configured trials, never by elapsed campaign days or level alone. Merge missing additive fields when loading an older cloud document or backup instead of overwriting new local fields with an old-schema object. Never replay a dramatic moment on app open.

Use dependency-free browser modules loaded before `app.js`: `system-progression.js` owns additive migration, event ledger, stat totals, titles, momentum and fast/slow trial outcomes; `system-trials.js` calculates the four stat-part bars and their event timestamps; `system-dashboard.js` renders the opening card, Status window, accessible evidence forms, moments and Website soldiers. Keep `app.js` as the existing state owner and adapter: map actual quest completions and Website changes to one stable, timestamped event each, render the modules, and leave the existing XP/scoring formula unchanged. Put every new point weight, target, time window, adaptation factor, momentum reward, Gate requirement, rest/workout constraint, effect duration and reward in one `system` block in `program-config.js`. No other source of user data is needed.

The first E→D trial starts at migration time; newly recorded reply, idea-application and quote evidence are required, while existing real workout sessions and sale/earnings records remain valid evidence. Workout requirements use complete Sunday–Saturday calendar weeks from the existing campaign start (Saturday stays a full rest day); this preserves logged weeks and keeps the 14/21/28-day windows and faster-next-trial rule feasible. Deadlines still start at each trial. When a legacy earnings record has only a date, label its time-of-day unavailable rather than fabricating precision.

Fast and slow timing compares the real trial start/finish timestamps against the configured active trial window; an accepted lighter seven-day block pauses the deadline and does not reduce the trial’s final workout/reading/reply/sale goal. On-time completion leaves the next trial unchanged. Slow trials show a logged weekly mini-step for ten actually sent owner messages without lowering external-outcome targets. A lighter-week offer is user choice, targets Strength or Intellect only, and records the trial offered so it is not offered in consecutive trials. Gate prompts are optional, expire after their configured hour with no penalty, do not auto-complete, and only award their configured reward after required evidence is entered. A stat is stale based on its latest real stat-changing event; the offer itself changes no stat. Momentum fills once per newly completed required-quest day, decays by exactly one step on each missed non-rest day, does not count Saturday, and stores per-day awards so reload/import cannot award XP twice.

The Status home includes the Player: Adam rank/level/XP card, a 2×2 stat panel, today’s actual quests, the current rank trial, momentum, a Saturday report and Website-Shadow-Army count/link. Retain the existing Quest, Library, Websites and Days views, program setup, backup/restore, sign-in and offline flow as usable destinations, placing the legacy account/settings controls behind a disclosure on Status. Reuse existing task and Website records rather than creating substitute or duplicate activities. Expose new manual evidence as small, optional forms that log what the player actually did. A website’s current Saved screenshot card is reused as its soldier’s card; Built/Sent/Replied/Sold states strengthen the silhouette and Sold is labeled Knight. Never fake replies, sales, testimonials, workouts, reading or earnings.

The visible app stays free: screenshot images are already compressed, the tracker-size guard remains below the Firestore 1 MiB document ceiling, and all new progression events share the existing synced state. Firebase configuration/security rules do not change. No paid service or browser storage outside the current `sys90` key is added. Version the service-worker cache and precache the new JavaScript so the existing installable offline PWA remains functional.

## Project structure and responsibilities

- `public/index.html`, `public/system.css` — installable entry point, shared mobile layout, navigation and System component styles; load progression, trial and dashboard modules before `app.js`.
- `public/app.js` — authoritative existing state and legacy quest flow, local-first save/backup/import, Website tracker, navigation, event-to-progression adapter and render dispatch. Preserve the legacy XP formula and ordinary Quest/Days/Library behavior.
- `public/program-config.js` — existing campaign defaults plus the single editable `system` settings block.
- `public/system-progression.js` — schema-safe state initialization, idempotent timestamped event upsert/deactivation, stat totals, title derivation, momentum and timing adaptation.
- `public/system-trials.js` — deterministic rank-trial criteria, weekly blocks, additional streak condition and completion-time evidence.
- `public/system-dashboard.js` — escaped and accessible presentation templates for the two-second opening, Status card, trial forms, Gate, moments and screenshot-backed Website soldiers.
- `public/shadow-art.js`, `public/shadows.css` — retain daily quest shadows; reuse its safe SVG for Website soldiers and the ARISE moment.
- `public/sw.js`, `public/manifest.json` — cache-version, offline precache and matching dark theme color.
- `public/firebase-auth.js` — unchanged sign-in/Firestore adapter; new records sync through the same existing account document.
- `tests/app.test.mjs` — frozen XP/completion, PWA/Website, Status, migration, real-action, trial timing and Saturday-rest regressions.
- `README.md`, `TODO.md`, `plan.md` — document the implemented controls, transparent design/number assumptions, delivered outcome items and unresolved Firebase security check.

## Design details and explicit assumptions

- **Design movement:** minimal dark tactical dashboard with restrained dark-fantasy shadow motifs; use an authored layout rather than generic panels or bright gamification.
- **Core principles:** preserve the user’s campaign history; award progress only for a recorded action/result; quiet daily UX, dramatic real milestones; accessible controls and optional effects.
- **Color philosophy:** approximately 90% is near-black/navy. Background `#07090F`, cards `#0D121C`, thin outlines `#1B2A44`, body text `#E8F1FF`, muted text `#7C8AA5`; ordinary active/progress/completion blue `#3FA9FF` and `#1E6BFF`. Reserve shadow purple `#7B3FE4` for Website army/ARISE, gold `#F5C451` for rank-ups/titles/first-sale (the explicitly requested B/A/S rank badge colors are a narrow exception), and warning red `#E5384B` for missed quests/penalties. Keep text contrast strong and glow very soft, only on focus, a tap, or a just-changed result.
- **Layout paradigm:** mobile single-column with a compact rank header, the explicitly requested two-by-two stat grid, progress summary, concise daily quest rows, four-part trial bars, and quiet trailing momentum/army/report; preserve bottom navigation and use a disclosure for less-used account/settings panels.
- **Signature elements:** thin electric-blue progress bars; a quiet rank plate with earned-gold title chips; smoky, screenshot-backed soldiers that visibly strengthen through Website status.
- **Interaction philosophy:** user-entered forms describe actions/results already performed; all controls remain explicit; a Gate may be ignored, and a lighter week is never automatic; persistence is local-first and account sync reuses the existing record.
- **Animation:** two-second, skippable Player: Adam intro then fade to Status; no reward, sound or vibration merely for opening. Level moments use a darkened page and restrained blue panel; the most prominent rank-up is gold; first paid sale is gold; new Website soldiers join through purple ARISE. Trigger each moment once on the corresponding new state transition. Honor `prefers-reduced-motion`; sound defaults off, and device vibration is feature-detected.
- **Typography system:** reuse native `system-ui` (no network font), medium body copy with strong sunlight contrast, concise uppercase section labels, sentence-case actions, and tabular numerals for totals/time.
- **Brand essence:** a personal discipline-and-business tracker where rank records real execution, not calendar time; deliberate, direct, earned.
- **Brand voice:** respectful after sustained work and brief/cold without shaming after missed days. Example streak: “You kept the line. Streak: 4 days.” Example miss: “Missed: Outreach. Next: send one useful message.”
- **Wordmark & logo:** preserve the existing System app icon/manifest and plain `SYSTEM` wordmark; no replacement logo, external font, or decorative hero asset.
- **Signature brand color:** System blue `#3FA9FF` for everyday navigation and verified completion/progress.

### Chosen configurable values and assumptions

- Retain the existing 90-day calendar, October 24, 2026 start, quest schedule, XP curve, current earned level and existing derived rank. Seed rank once and create the first new trial at upgrade time; exact pre-upgrade reply/quote/trial timestamps are not invented.
- Trial windows: E→D 14 days (specified); D→C 21 days; C→B 28 days. The latter two are explicit configurable planning assumptions; on-time completion leaves the next trial as written.
- Fast trial: 1.25 effort factor for eligible effort targets, 0.75 next-window factor, 100 XP and earned `Fast climber` title. Replies, testimonials and paying clients remain at their specified count; never scale them.
- Slow mini-step: ten real owner messages in a seven-day step. Lighter option: seven days with three Strength sessions/one Intellect idea, selected by the user, never offered in two consecutive trials; it pauses the deadline and does not change final requirements.
- Stat-point defaults: reading 5, learning 5, Strength workout/bonus workout 10, outreach quest 5, real outreach message 1, Website Sent 10, owner reply 25, testimonial 15, applied reading idea 8 Intellect points plus one real-message Influence point, completed book 10, paid site 50, and 1 Wealth point per Ksh 100. Ksh earnings accumulate fractionally in the Wealth total; the editable values live only in `program-config.js`.
- Momentum: seven steps with increasing XP `[0, 2, 4, 6, 8, 10, 12, 15]`. Each incomplete non-rest day loses one step; Saturday causes neither loss nor gain. Existing completed-day records do not retroactively earn a new bonus at migration.
- Gate: after five stat-stale days, allow an optional one-hour challenge; repeat offer for a stat is cooled down seven days; clearing pays 100 XP. Defaults: one Strength workout/25 reps, three Intellect pages plus a note, five Influence messages, or one Wealth owner quote.
- Intro two seconds; level moment 4.2 seconds; rank moment 6.5 seconds. Saturday is weekday index 6. Workout qualification uses complete Sunday–Saturday campaign-calendar weeks with no Saturday workout; trial deadlines are timed from their actual start. The final C→B stretch counts real non-shielded required-quest days only.
- Manually entered outcomes are self-reported. `Sold` is treated as paid-client evidence; the user’s previously saved money values are read from the existing KES field; no purchase or contact is made by the app.
- Existing Firestore rules/auth domains still need console verification; the app cannot establish this from source-only checks, and they will not be modified by this upgrade.
